## 需求合理性与方案选择

合理（静态推理，未在本地执行验证）：PageHeader 和 SettingsField 已存在，但语音页私有 Card/标题/输入组合与宿主跨页覆盖仍分散；主题配置不能替代 JSX 结构收敛。证据为调查文档和台账中的 `console/src/pages/Settings/VoiceTranscription/components/TranscriptionModelCard.tsx:17`、`console/src/pages/SettingsCenter/index.module.less:676`。

曾比较 A 基础组件＋规范、B 小型字段组合、C 全页模板。A 成本低但一致性依赖人工；B 收敛字段而保留页级差异；C 覆盖结构与状态布局，需处理搜索、混合内容和样式边界。人类要求所有页面纳入调研后确认 C 修订方案：统一骨架＋内容组合＋专用布局例外，不将单一语音页通过当作总体验收。

## 冻结的跨层契约

本任务前端展示层先行且仅修改前端与文档；没有后端先行任务，也没有待新增的 API、错误码或事件。

- 保留现有 API 方法、路径、请求字段、scope/Agent/实体、响应解读、错误映射、事件及订阅生命周期。相同输入/操作序列产生相同业务请求目标、负载、触发与次数。实施者在迁移前从本页实际调用点记录这些信息，不能按模板名称猜测协议。
- `useAutoSave` 的 schedule/flush/discard/requestClose 原样消费；模板不得新增总保存、重试、导航守卫或成功推断。
- PageHeaderProps、SettingsField 的 Form.Item 属性及 SettingsDrawer 关闭机制保持兼容；新组件签名以第 III 节为准。
- search target/open/tab/labels、aria-controls、Form 名称、组件 key 和上下文保留；模板不持有业务状态、不通过条件挂载清除表单。
- Models 的 global scope、语音多请求保存、Config/Security 不同切换顺序不统一。请求失败恢复、只读与权限控制由原业务处理。

## 旧路径删除与回退

P1 接入一页再退出该页旧覆盖；页面私有重复布局在行为与截图通过后同批删除。P2 继续逐页清理，不删除仍被 P3/插件使用的选择器。P3 对剩余消费者取证后才删除确实无消费者的规则。既有交互控件、业务 hook、历史路由、插件注册接口不因外观统一被删除。每次回退仅回退对应展示提交，不能恢复或覆盖用户业务数据。
