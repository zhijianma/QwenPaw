# 首屏资源按需加载：短设计与验证清单

状态：用户已确认本文；进入实施计划编写阶段，尚未修改实现，不提交。

## 目标与边界

先消除静态依赖，再处理空闲时的提前下载。降低首屏资源开销，保持现有功能。

- 直接打开聊天页时立即加载聊天包，不人为延迟消息显示。
- 设置等非聊天页面不因全局初始化下载完整聊天实现；页面实际需要 Markdown、附件等组件时，允许加载对应实现。
- 统计图表在打开趋势或统计页面时加载，普通聊天不加载统计图表包。
- 不改会话状态来源、分页逻辑、插件 API、后端存储、迁移、fork、checkpoint 或 backup 语义。
- 保留 10 MiB 原始体积、3 MiB Brotli 门槛；不关闭预加载来掩盖静态依赖，不删除功能，不新增依赖或兼容层。

## 方案取舍

| 方案 | 收益与代价 | 决定 |
|---|---|---|
| 定点调整共享依赖归属及初始化加载边界 | 保留大部分分包结构，分阶段确认影响；需明确共享模块边界 | 采用 |
| 全局启用仅显式模块分包，让 Rollup 重新分配共享依赖 | 更系统，但会改变更多分包、循环关系和执行顺序 | 本轮不采用 |

不把聊天和图表包的总大小直接视为可节省体积：共享依赖及样式仍需保留，收益以生产构建与网络实测为准。

## 阶段一：只消除静态依赖

优先只修改 `console/vite.config.ts` 的局部分组规则：

1. 将全局需要的 KaTeX CSS 从聊天实现分组中隔离，仍由 App 全局导入；保持公式样式的内容、加载时机与顺序要求。
2. 将聊天与图表共用的 lodash 及其构建包装模块放在中立的共享分组中，避免为使用 lodash 加载图表实现。
3. 保留其他分包规则和全部插件初始化时机，不全面拆分 UI 包。

验收静态入口及其传递依赖，而不只检查 `index.html` 中的预加载标签。阶段一允许空闲初始化仍下载聊天包，不能宣称已完成真正按需加载。

## 阶段二：消除空闲初始化的非必要下载

阶段一通过后单独实施：

1. 保留插件基础 API 的初始化和可用时机。会话 hooks 仍读取 SDK 原有的同一个 Context，不创建替代状态，不使用 URL 推导替代会话状态。
2. 优先通过 SDK 已有内部入口与局部分包边界隔离轻量 hooks，避免加载完整聊天渲染实现。仅改为深层导入并不足以保证有效，必须检查实际模块图及 Context 单例。
3. 保留内置工具卡片的注册时机、名称和插件覆盖优先级，将注册描述与重型实现加载分离；首次使用时加载实现，使用已有加载和错误边界。不得暂时显示错误的通用卡片，也不能丢失加载期间的最新流式内容。
4. 实际需要聊天渲染的其他入口（例如 Inbox、插件页面）同样按使用加载，不简单用“是否聊天路由”禁止加载。

若 SDK 内部循环依赖导致无法在保留同一 Context 的前提下隔离，或必须改变插件同步 API 才能实现，应先更新设计确认范围，不在本轮暗中改状态模型或扩大为 SDK 重构。
