## 所有权与状态模型

业务 hook、Form、store 和流程控制器继续拥有数据、草稿、校验、请求、
作用域与操作生命周期。模板仅接收业务层能够证明的状态与动作，负责呈现。
不增加全局配置 store、不复制表单值、不引入统一保存队列或事务。

使用两个相互独立的维度描述页面/区域，具体 TypeScript 接口留待第 III 节：

- 内容状态：尚无可用内容、正在加载、已可用、已确认无数据、加载失败。
  已有内容上的刷新、局部失败、过期提示是附加信息，不替换整个页面。
- 操作状态：无操作、请求处理中、已确认完成、失败；若业务提供草稿/
  校验状态，可展示尚未提交或校验提示。没有数据来源的状态不凭空推断。

“未提供状态”不等于成功；loading=false 不等于成功或空列表。
内容加载与保存是两条独立生命周期，不合并成全页 busy 布尔值。

## 呈现与恢复规则

| 条件 | 呈现 | 动作与保持内容 |
| --- | --- | --- |
| 初次读取未完成 | 保留页头与稳定内容占位 | 不提前显示空列表或默认设置已生效 |
| 初次读取失败且无可用内容 | 内容区域错误及原有恢复入口 | 不显示成功态，不用空数据掩盖错误 |
| 读取成功且确实无结果 | 区分无数据与筛选无匹配 | 仅展示已有的创建、清除筛选等动作 |
| 已有数据刷新 | 原有内容可用时继续可见，局部标记刷新 | 不因刷新卸载编辑器；不可用性仍由业务决定 |
| 部分请求失败 | 在失败区域显示警告/错误 | 保留其他有效区域；不宣称整页加载完成 |
| 写入/任务处理中 | 在对应动作或区域反馈 | 原有重复提交控制继续生效，不默认禁用整页 |
| 操作成功 | 仅反映业务确认的操作结果 | 保存成功不等于安装、恢复等后续任务已完成 |
| 校验或请求失败 | 字段/区域可恢复提示及原有动作 | 不重置草稿；不自行补发、撤销或重试写请求 |
| 只读/无权限 | 使用原有能力判据与说明 | 模板不改变隐藏/禁用策略，也不承担授权校验 |

网络中断、服务器拒绝和校验失败只在业务提供可区分信号时使用不同文案；
不能将所有异常猜成离线，或新增不存在的错误码。没有失败分类的页面沿用
真实的通用错误，而不是在模板中编造精确原因。

状态至少按区域或操作区分；Models、统计页和日志页不强制拥有同一个
“页面已保存”状态。局部成功不能盖掉同页其他失败或尚未结束的操作。

## 保留现有保存和导航语义

| 已有机制与证据 | 模板迁移约束 |

模板不改变 Tab 的 key、组件身份和挂载策略，也不因显示 pending/error
而重新创建 Form。Drawer、Modal 的关闭仍调用业务 onClose/requestClose；
视觉上的关闭按钮不能绕过原有 flush、取消、确认或焦点恢复路径。

后台任务与界面关闭分离：关闭操作层不自动等于取消任务，任务完成也不
自动等于当前页面仍属于原操作目标。取消按钮继续调用已有业务取消入口。

## 状态来源与失败隔离

新增静态依据：`console/src/pages/Settings/Models/useProviders.ts:23`
使用 Promise.allSettled；`:27` 将供应商读取失败作为错误，`:35`、`:41`
对默认模型读取失败保留 providers 并提供 warning；`:71` 静默刷新。
模板必须能表达“内容可用＋局部警告”，不能只接收 loading/error 二选一。

useAutoSave 目前只暴露 schedule、flush、discard、requestClose，未暴露
完整响应式保存状态；首轮迁移保留其失败重试反馈，不凭计时器显示“已保存”。
已有业务可提供准确 saving/result 的页面可呈现局部反馈。若需要新状态
观察接口，应在第 III 节单独论证，不能为了统一提示偷偷重写保存调度。

作用域由业务判定：页面 route、Agent、实体和请求版本只作为已有数据
所有权的依据，不从导航分组名称推断。例如 Models 查询是 global
（useProviders.ts:25），即使 Agent 变化会触发刷新（:64），也不是 Agent 私有配置。
模板不得将上一个实体的成功或失败提示复用到新实体，也不自行引入全局缓存。

## 两个核心不变量及验证场景

1. **状态真实且局部归属明确**：没有后端/业务确认不显示成功；局部失败
   不被其他区域成功覆盖；加载完成不代表写入完成；新作用域不继承旧提示。
2. **展示迁移不改变操作次数、目标和顺序**：相同有效输入及操作序列下，
   保存请求的目标、负载、触发条件、次数和关闭/切换结果与原契约一致。

后续特征验证应覆盖：模型局部加载失败仍可使用供应商列表；心跳校验失败
与 Agent 切换；配置分区保存失败的切换结果；环境变量创建/编辑差异；
备份确认取消、先备份失败/成功及恢复推进；自动保存失败重试和关闭确认。
这些是待执行的验收场景，不是本轮通过结论。
