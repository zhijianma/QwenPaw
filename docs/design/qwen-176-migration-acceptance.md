## 范围与顺序

推荐分批覆盖：全部 36 个源码入口都有迁移或专用布局处置记录；先用
跨类型真实页面验证公共模板，再推广其余配置页面。每批通过后才能进入
下一批。语音转录只是条件表单样例，不能成为模板或本项目唯一验收依据。
以下实施范围已于第 8 轮获确认；按批次验收推进，不等同于一次性全量迁移。

| 批次 | 覆盖入口（相对 console/src/pages） | 退出条件 |
| --- | --- | --- |
| 0 基线与契约 | 全页面矩阵、宿主、原公共组件消费者 | 36 项均有宿主/可达性/类型/状态/保存与关闭/搜索/处置记录；待改页面先取得基线截图与可复现数据 |
| 1 跨类型模板验证 | SettingsCenter 宿主；Control/Heartbeat、Agent/Config、Settings/Security、VoiceTranscription、Models、Environments、TokenUsage、Debug、Backups、Import | 表单、多分区、集合编辑、数据/日志、流程全部接入并通过对应行为及截图验收；共同组件与贡献指南一起交付 |
| 2 其余配置与管理集合 | SettingsCenter/GeneralSettings、NavigationSettings；Settings/OffloadPolicy、Community、Agents、SkillPool、AgentStats、PluginManager；Control/Channels、CronJobs、Sessions；Agent/ACP、MCP、Tools、Skills | 逐页采用适用组合；导航拖拽、日历等特殊内容保留；每个实际改动页面单独验收 |
| 3 专用布局与收口 | Market、Market/Community、AppCenter、Settings/PawApps、Inbox、Agent/Checkpoints、Files、Chat、Login、Hub | 保留专用骨架，完成公共控件/视觉规范适用表与宿主回归；仅修正经盘点确认属于本需求的一致性问题，不新增业务功能 |

上表按入口分配为 1 个宿主＋10 个跨类型页面＋15 个推广页面＋10 个
专用布局入口，共 36 项。批次 0 遍历同一集合，不额外增加入口数。
专用布局例外只豁免配置骨架，不豁免公共视觉规则和受影响行为的验收。
若某专用布局无需改动，明确记录理由和检查结果，不为凑迁移数量改代码。

实际部署不可达的历史入口仍保留源码处置记录，注明可达性证据和原因；
不伪造页面截图。无法取得必要角色、页面或数据的项目标未验证，不能宣称
全部验收通过。动态插件核对当前安装清单和宿主隔离，不承诺未知第三方
页面重写；本次不新增插件 SDK，也不顺带删除历史入口。

备选为一次性全量迁移：可以减少新旧共存期，但在搜索和跨页 CSS 风险
尚未得到跨类型验证前扩大改动面，因此推荐上述分批顺序。批次边界是
验收边界，不要求按组件层和页面层拆成彼此无法独立验收的子 issue。

## 视觉方向与尺寸

沿用已确认的暖中性色、品牌橙、克制层级；复用现有主题 token。
统一页头与内容起始边界，以分区和间距组织信息，不给每个字段增加卡片。
SettingsSection 的 readable 建议上限 48rem、同时不超父容器；full 使用
可用宽度。该尺寸属于本节已确认的设计取值，必须在下列视口下验证，
不能让日志、图表、表格、嵌入页面或长文本编辑器受窄表单限制。
移动端按既有间距尺度收缩，操作可换行，重要状态与动作不隐藏。

## 截图与人工验收

任何页面或共享样式修改前，先记录即将受影响页面的原版；修改后与同一
路由（含查询参数）、权限、Agent/实体、数据集、视口高宽、缩放、主题、
语言和状态配对。原版须记录实际服务对应的提交，不能假设运行中的服务
就是当前受管 worktree。缺少原版时不能用生成图或事后效果图冒充。

每个改动页面至少交付默认状态和最密集有效状态的前后对照；适用的加载、
空态、局部失败、提交中、失败恢复、只读和弹层状态另列覆盖表并提供
能说明变化的截图。纯瞬态以可重复的受控场景截取，并标明模拟条件。
截图文件与对照索引作为 issue/PR 附件交付，按页面、状态和环境一一对应，
附变化说明；敏感值使用固定脱敏数据，不靠遮盖消除实际布局问题。

按 design.md 的 Rendered experience matrix 执行：375、768、1280px
宽度，200% 缩放，内置浅/深主题，主题敏感处加一组自定义强调色；中英文、
长标签、密集数据；键盘、指针和适用的触摸；默认及 reduced motion。
不要求所有维度做无意义笛卡尔积，但必须逐项有记录，布局变化处提供
对应宽度截图，主题变化处提供对应主题截图。各对截图条件完全一致。

判定阈值：页面级非预期横向溢出、不可达操作、重要内容裁切、重复页头、
新增双层主滚动、焦点丢失、主题硬编码残留均为 0；每个必需状态及流程
均有结果，不用截图替代保存次数、请求目标和错误恢复的验证。
视觉收益由对照中的层级、对齐、密度、可读性说明及人工接受判断；不设
“像素差越小越好”的指标，也不把截图数量当作专业设计感的充分证明。

## 行为特征验证与定点命令

保持第 II 节的请求目标、负载、触发时机、次数与关闭/切换结果。迁移前
在当前工作提交补齐必要特征测试，确认契约；每次布局迁移后运行相同
受影响测试。无需切换到旧提交执行整套测试。需要补充的断言应覆盖：

- Heartbeat 的校验、旧 Agent 草稿归属；Config 与 Security 不同切换顺序。
- Models 的默认模型局部失败保留供应商；刷新不卸载编辑内容。
- Environments 创建显式提交、编辑自动保存及失败关闭确认。
- Backups 取消不推进恢复、先备份成功才推进；Import 保留目标与取消。
- 搜索打开分区/弹层后的目标定位、键盘焦点返回、权限及主题隔离。

已存在的定点入口可从 console 目录运行，例如：

```sh
node --max-old-space-size=4096 ./node_modules/vitest/vitest.mjs run \
  src/hooks/useAutoSave.test.tsx \
  src/pages/Agent/Config/components/RuntimeWorkbench.test.tsx \
  src/pages/Settings/Environments/index.test.tsx \
  src/pages/Settings/Models/useProviders.test.ts \
  src/pages/Settings/Backups/restore/useRestoreFlow.test.ts
```

阈值为命令退出码 0、选定用例失败 0，且不得通过跳过契约断言取得通过。
最终计划按实际改动列出新增/补充文件与逐批命令；上面不是所有页面的
完整测试清单，更不是已经执行的结果。源码存在测试不等于它覆盖全部
契约，实施者须先核对断言。浏览器负责验证 DOM mock 不能证明的布局、
真实滚动、焦点、弹层和主题。禁止全量 build/format/test 或新增依赖来
绕过定点验证；若工具能力不足，记录缺口，不用静态测试冒充浏览器验收。

## 清理、回退与贡献指南

每页先保持业务 hook 和标识不变，接入骨架，再替换重复布局；该页公共
样式覆盖的退出与接入在同一批完成。行为检查、浏览器与截图验证通过后
才删除该页无消费者的私有布局规则。其他页面仍在使用的旧选择器保留，
最后一批确认无消费者才清理；不用扩大选择器或 !important 掩盖冲突。
失败时回退该批展示迁移，保留用户数据，不修改业务配置以迁就截图。

贡献指南交付组件使用表、四类组合示例、专用布局例外、状态来源与保存
边界、搜索属性、主题/滚动规则、验收 checklist。外部贡献者与 AI Agent
使用同一份规范，新增页面须说明组合方式及验证结果，不复制私有模板。

## 两个核心不变量

1. 全部入口都有明确处置，每批按页面和状态验收；跨类型首批通过后再
   推广，专用布局保留，不以语音页或少数截图代表全部完成。
2. 每个实际改动页面提供可追溯、同条件的前后截图，同时证明业务与交互
   契约不变；缺证据的项目不得写成通过。
