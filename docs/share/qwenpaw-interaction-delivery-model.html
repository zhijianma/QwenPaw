Problem · Direction · User Value

可靠交付，而不是继续堆功能

QwenPaw 已经具备丰富的 Agent、工具、安全和扩展能力，但尚未形成 让用户容易开始、放心执行、清楚查看结果并持续复用的产品闭环。

查看当前问题 查看解决方向
核心转变
从拥有很多能力的 AI 助手，转向主动承接工作、可靠交付结果、 并把成功经验转化为持续能力的 Agent 工作台。

QwenPaw 的差异应建立在工作闭环、可信执行、结果交付和能力复利上。

01 · Current Problems

QwenPaw 当前的问题

问题不是缺少模块，而是能力、入口、状态和结果没有围绕同一项工作 形成完整闭环。

01

能力分散，工作闭环不完整

Chat、Goal、Cron、Harness、Approval 等各自承载部分状态，用户难以判断工作在哪里、是否完成。

02

产品仍以 Chat 为中心

复杂任务被压进消息流，目标、计划、审批、恢复、产物和验收没有成为一级对象。

03

长任务和无人值守不够可靠

后台运行、重启恢复、幂等重试、预算、退出条件和异常接管缺少统一契约。

04

轨迹可见，但因果和结果不清晰

Policy、Approval、Audit、Checkpoint、Artifact 与 Verification 尚未串成完整因果链。

05

一次任务难以形成能力复利

成功流程和失败经验散落在对话中，自动化、工具、Skill 和插件缺少统一沉淀与治理。

02 · User Needs

用户真正关心三个问题

用户不关心内部有多少 Runtime、Mode 或 Harness，而关心如何开始、 如何完成以及在哪里看到结果。

NEED 01

如何方便开始

简单问题直接 Chat，明确交付创建 Task，复杂对话可升级 Task，重复工作可转 Automation。

  • 系统建议模式
  • 用户无需判断复杂度
  • 不强迫所有问题创建 Task
NEED 02

如何可靠完成

简单工作即时完成，复杂工作后台执行，成熟流程无人值守，异常和越权时请求接管。

  • 计划、预算与权限
  • 重试、恢复与 Checkpoint
  • 完成前 Verification
NEED 03

如何清楚查看结果

Chat 看回答，Task 看进度，Inbox 收回复和结果，Artifact 看最终交付与验证。

  • 过程与结果分层
  • 来源和证据可追溯
  • 成功经验可以复用

03 · Target Model

统一产品闭环

Chat、Task 与 Automation 入口不同，但必须共享同一 Work Runtime、 因果链、结果交付和能力复用机制。

ENTRYChat / Task探索或明确交付
TRIGGERAutomation时间、事件与 Webhook
RUNTIMEUnified Work目标、计划、执行、恢复
TRACECausal Graph发生了什么与为什么
DELIVERYInbox回复、结果、审批、异常
OUTCOMEArtifact版本、证据与验证
GROWTHCapabilities知识、流程、工具与插件

04 · Directions

四个解决方向

不再增加平行模块，而是围绕统一工作、可靠执行、结果交付和能力复用进行收敛。

D01

双入口与统一 Work

Chat 用于交流探索，Task 用于明确交付，Automation 创建标准 Work。

  • Chat 可无损升级 Task
  • Goal、Plan、Run、Artifact 使用同一身份
  • Work 是唯一事实源
D02

可靠运行与因果可观测

从一次 Agent Run 升级为对完整 Work 负责。

  • 后台、恢复、重试与幂等
  • L1–L3 自治等级
  • Tool、Policy、Approval、Checkpoint 与验证因果关联
D03

Inbox 投递与 Artifact 交付

Inbox 不取代 Chat，只投递回复、结果、审批与异常。

  • 普通 Timeline 不制造噪声
  • Artifact 具备来源、版本与验证
  • 结果可验收、修改、分享和归档
D04

能力复用与稳定扩展

将成功工作转化为 Knowledge、Skill、Workflow、Tool、Automation 与 Plugin。

  • 结构化复盘与候选评分
  • Capability Registry
  • 版本化 Manifest、Slot、健康与回滚

05 · Roadmap

P0–P2 迭代路线

每一阶段都以用户价值和可验证结果作为完成标准。

P0

完成用户工作闭环

双入口、统一 Work、Inbox、Artifact 与重启恢复。

用户价值：更容易开始，离开后不丢结果，回来即可继续。
P1

无人值守与可信执行

后台持久运行、自治等级、因果图、幂等副作用与自动验证。

用户价值：无需持续盯守，同时清楚系统做了什么和结果是否可信。
P1

插件契约与自动化

Manifest、SDK、官方迁移、热安装，以及时间与事件创建标准 Work。

用户价值：能力安装即可使用，扩展和升级风险更可控。
P2

能力飞轮与 Hub

任务复盘、Registry、使用反馈、外部事件、团队调度与能力分发。

用户价值：QwenPaw 越用越懂用户，成功工作持续形成新能力。

06 · Product Profiles

同一核心，三种配置

Lite、Workstation 与 Hub 不是三套代码，而是同一 Runtime 在不同信任边界和规模下的装配。

LITE

轻量个人 Agent

快速 Chat、轻量 Task、个人 Inbox 与文档、文件和报告 Artifact。

WORKSTATION

本地与内网开发工作台

仓库、Coding、后台任务、本地自动化和插件开发验证。

HUB

外部事件与团队中枢

Webhook、集中调度、团队审批、审计、能力分发和组织 Artifact。

07 · Difference & Value

差异不在功能更多

QwenPaw 应通过可靠完成、可信解释、结果交付和能力复利来建立差异。

VS CHAT ASSISTANT

从回答走向交付

Chat 与 Task 并列，支持后台、恢复、Artifact 和 Verification。

用户得到的是可验收结果，而不只是一段回答。

VS CODING AGENT

从代码工具走向通用工作台

统一承载代码、文档、知识工作、自动化和长期任务。

用户无需为不同任务切换多套孤立工具。

VS AGENT CONTROL PLANE

从管理 Agent 走向管理结果

强调统一 Work、可信执行、因果可观测与结果验证。

用户只需管理目标、例外和结果。

VS AUTOMATION PLATFORM

从固定流程走向可判断、可恢复

Agent、Workflow、Policy、Approval、Recovery 与 Verification 处于同一闭环。

自动化可以解释、恢复、验收并沉淀经验。

08 · Measures

如何判断方向有效

不看菜单、工具和插件数量，关注用户是否更容易开始、任务是否可靠完成、结果是否可信和能力是否复用。

  • 开始成本完成首项工作所需步骤与配置
  • 完成质量任务验收通过率与失败恢复率
  • 无人值守无人工介入完成率与重复副作用率
  • 可信结果Artifact 可追溯率与 Verification 覆盖率
  • 结果投递Inbox 投递成功率与噪声率
  • 理解成本用户理解任务结果所需时间
  • 能力复用候选采纳率与复用成功率
  • 扩展质量插件安装、升级与回滚成功率

Final Position

让用户容易开始，让 QwenPaw 可靠完成，让结果清楚到达。

Chat 与 Task 并列，Automation 创建工作，Work Runtime 统一执行， Causal Graph 解释过程，Inbox 投递结果，Artifact 承载价值， Capability Flywheel 让每次成功成为下一次能力。
