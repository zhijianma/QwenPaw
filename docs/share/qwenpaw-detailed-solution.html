Detailed Solution · Capability Roadmap

从问题根因，到可验收的解决方案

在现有 AgentScope Runtime 之上建立统一 Work 领域层，将 Chat、 Goal、Cron、Harness、Approval、Checkpoint、Artifact 与 Plugin 逐步接入同一事实源。

逐项查看解决方案 查看实施路线
核心策略
不重写现有 Runtime，不新建平行任务系统；用统一 Work、因果事件、 结果交付和能力注册中心收敛现有能力。

每个方案必须具备领域边界、运行机制、用户价值与验收标准。

02 · Problem Solving

五个问题，五组解决机制

展开每项可查看根因、解决方案和具体建设重点。默认打开的是最基础的统一 Work。

01能力分散，工作闭环不完整多个入口和模块分别保存状态，无法形成唯一事实源。+

根因

Chat、Goal、Mission、Cron、Harness、Approval 与 Checkpoint 缺少统一身份和生命周期。

解决方案：Unified Work Domain

  • 建立 Work、Run、Step、Artifact、Evidence、Verification 核心对象；
  • Chat、Task、Cron、Webhook 只作为入口和 Trigger；
  • 所有状态转换由 Work Service 执行并记录 Event；
  • Console、CLI、Runtime 和 Plugin 通过同一应用服务访问。
02长任务和无人值守不够可靠后台、重启、重试、预算和异常升级没有统一契约。+

根因

一次 Agent Run 的连续执行假设，无法覆盖长期工作中的进程、网络、审批和副作用失败。

解决方案：Reliable Work Runtime

  • Execution Contract 声明权限、预算、重试、退出和验收；
  • L1 交互、L2 后台、L3 无人值守；
  • 持久队列、lease、heartbeat 与安全重新调度；
  • 幂等副作用、Checkpoint、Recovery 与 Kill Switch。
03轨迹可见，但因果不完整知道发生了什么，却无法解释为什么、影响什么和如何恢复。+

根因

Policy、Approval、Audit、Checkpoint、Artifact 与 Verification 使用不同记录方式，缺少因果关联。

解决方案：Causal Event Graph

  • 统一 Event Envelope、cause_event_id 与 correlation_id；
  • Timeline、Audit、Status、Cost、Recovery 均为同一事件源投影；
  • Tool、Policy、Approval、Side Effect、Artifact、Evidence、Verification 建立边；
  • 失败自动生成 Failure Summary 与推荐恢复点。
04回复和结果缺少稳定交付位置异步结果分散，Artifact 容易退化为附件或文件列表。+

根因

内容事实源、结果投递和长期交付物没有分层，用户必须重新进入原页面阅读过程。

解决方案：Inbox Delivery + Artifact Registry

  • Inbox 只投递 Reply、Result、Approval、Exception；
  • 不复制内容，只保存摘要、引用和处理状态；
  • Artifact 保存来源、版本、Evidence、Verification 与替代关系；
  • 支持验收、修改、分享、重新验证和复用。
05一次任务无法形成能力复利经验散落，Workflow、Automation、Tool 与 Plugin 缺少统一治理。+

根因

缺少任务复盘、候选分类、发布门槛、能力注册中心和使用反馈。

解决方案：Capability Flywheel

  • 任务结束生成结构化 Retrospective；
  • 候选路由到 Knowledge、Skill、Workflow、Tool、Automation 或 Plugin；
  • Capability Registry 保存来源、版本、权限和成功率；
  • 版本化 Manifest、标准 Slot、健康检查与回滚。

03 · Domain Model

最小稳定领域对象

公共 API 应围绕稳定领域对象，而不是页面、Provider 或具体 Harness。

D01

Work

用户希望完成的真实工作。包含 Goal、Acceptance、来源、权限、预算、自治等级和当前状态。

D02

Run

Work 的一次执行。记录 Executor、恢复来源、预算使用、开始结束时间与失败原因。

D03

Step

Plan 中可观察和恢复的步骤。包含依赖、状态、重试策略、Checkpoint 与 Artifact。

D04

Artifact

阶段或最终产出。保存类型、版本、存储引用、来源、Evidence 和 Verification。

D05

Event

领域事实。通过 cause_event_id 与 correlation_id 形成可投影的因果图。

D06

Capability

可复用知识、Skill、Workflow、Tool、Automation 或 Plugin，保留来源与验证状态。

04 · Unattended Runtime

无人值守的四个可靠性机制

无人值守不是放开权限，而是在明确目标、预算、Policy、恢复和退出条件内持续执行。

Execution Contract

声明 Goal、Acceptance、权限、副作用、预算、重试、升级与退出条件。

Queue & Lease

持久队列、Worker lease、heartbeat 与安全重新调度，避免僵尸 Work。

Idempotency

外部写入使用幂等键和 Side Effect Record，重试不重复评论、Push 或发布。

Checkpoint & Budget

绑定 Work/Run/Step，支持恢复、超时、费用上限和全局 Kill Switch。

06 · Delivery

Inbox 投递，Artifact 交付

将“用户现在需要关注什么”和“长期结果是什么”分开，避免所有内容挤在 Chat 与 Timeline。

Inbox Delivery

只投递需要用户关注的内容。

  • 异步 Chat Reply
  • Task 与 Automation Result
  • Approval Request
  • Exception 与人工接管
  • Artifact Ready 与 Verification Result

Artifact Registry

保存长期、可验收和可复用的结果。

  • 来源 Work、Run、Step
  • 版本、状态与 checksum
  • Evidence 与 Verification
  • 预览、比较、分享和重新验证
  • 提升为复用候选

07 · Capability Registry

复用资产的清晰边界

评分决定是否值得沉淀，类型规则决定形式，验证和权限门槛决定能否发布。

类型适合内容发布门槛
Knowledge稳定知识、规范和决策来源、范围、脱敏与后续复用
Template稳定输入输出结构真实任务验证与版本
Skill需要语义判断的经验输入输出、边界、成功与失败样例
Workflow可重复的多步骤过程失败、恢复、退出和 Artifact
Tool输入输出明确的动作Schema、单元测试、最小权限
AutomationTrigger 与 Workflow 的绑定幂等、预算、异常升级和结果投递
Plugin能力安装、分发和治理Manifest、兼容性、健康与回滚

10 · Roadmap

分阶段实施与退出条件

每个阶段只有在端到端验收通过后才进入下一阶段，避免同时铺开所有能力。

P0

用户工作闭环

Work 核心模型、Chat 升级 Task、Task 视图、Inbox、Artifact 和恢复基础。

退出：状态唯一、结果不丢、审批和产物可追溯。
P1-A

无人值守与因果图

Execution Contract、队列租约、幂等、预算、Causal Graph 与 Recovery。

退出：重启可恢复、无重复副作用、失败和完成可解释。
P1-B

插件契约与自动化

Manifest、SDK、generation 切换、官方迁移与 Trigger。

退出：安装按声明生效，Trigger 不绕过 Work。
P2-A

能力复用飞轮

Retrospective、Candidate Scoring、Registry 与反馈治理。

退出：完成执行、沉淀、复用、反馈闭环。
P2-B

Hub 与团队场景

多用户、多仓库、多节点、团队治理与组织分发。

退出：外部事件持续运行，团队结果可追溯。

11 · Risks

主要风险与控制

方案是否可行，不只看能力是否存在，还要防止架构再次分裂和产品再次复杂化。

平行 Runtime

复用 AgentScope；Work 只统一身份、状态和治理；Harness 通过 Executor Contract 接入。

Inbox 噪声

只投递 Reply、Result、Approval、Exception；普通 Event 留在 Timeline。

因果图过度复杂

先覆盖 Tool、Approval、Side Effect、Artifact、Verification 主链。

无人值守越权

L3 强制 Policy、Budget、Exit Conditions、幂等与 Kill Switch。

低质量能力堆积

候选不自动发布，要求真实复用、验证、成功率和生命周期治理。

Edition 代码分叉

共享 Domain、Runtime、Contract；Edition 只做装配和默认配置。

Final Outcome

让用户容易开始，让 QwenPaw 可靠完成，让结果清楚到达。

统一 Work 负责工作事实，可靠 Runtime 负责完成，因果图负责解释， Inbox 与 Artifact 负责交付，能力飞轮负责持续复用。
